# Tarang

Tarang is Team Ocelleon's IoT Challenge 2026 project for a clinical wearable pipeline that combines physiological sensing, embedded firmware, Bluetooth communication, and ECG-oriented machine learning.

## Repository layout

Software projects are stored under [projects/](projects/) as required by the IoT Challenge 2026 template.

```text
projects/
  tarang-firmware/  Silicon Labs EFR32MG26 firmware project
  tarang-ml/        ECG classification notebook and training workflow
```

Supporting repository files remain at the root:

- [.github/](.github/) contains pull request, issue, ruleset, and workflow configuration.
- [agent_guidelines/](agent_guidelines/) contains team workflow guidance.
- [LICENSE.md](LICENSE.md) contains the Apache 2.0 license.

## Hardware requirements

- Silicon Labs EFR32MG26 target board
- ECG analog front-end or compatible ECG signal source
- IMU sensor interface
- PPG sensor interface
- BLE-capable phone or central device for testing

## Firmware project

The firmware project is in [projects/tarang-firmware/](projects/tarang-firmware/).

Open [projects/tarang-firmware/Tarang_Core_Pipeline.slcp](projects/tarang-firmware/Tarang_Core_Pipeline.slcp) in Simplicity Studio, install the matching Silicon Labs SDK locally, then build and flash the project from the IDE.

Generated SDK folders, project checksum files, and build outputs are intentionally ignored by Git.

## Machine learning project

The ML workflow is in [projects/tarang-ml/](projects/tarang-ml/).

Open [projects/tarang-ml/tarang_ecg_classifier.ipynb](projects/tarang-ml/tarang_ecg_classifier.ipynb) in Jupyter. Training outputs such as plots, Keras models, and TFLite files are regenerated by the notebook and are intentionally ignored by Git.

## Git workflow

Follow the simplified trunk-based workflow from the challenge guide:

- Keep `main` stable.
- Use `feature/<short-task-name>` for new work.
- Use `bugfix/<issue-name>` for fixes.
- Open pull requests into `main`.
- Require at least one teammate review before merging.
